## 2. หน่วยการเรียนรู้และผลการเรียนรู้ 14 ข้อ

จากเอกสารโครงสร้างรายวิชา (`4แบบโครงสร้างรายวิชา111.pdf`)

### หน่วยที่ 1 โครงสร้างโปรแกรมภาษา C และการรับ-แสดงผลข้อมูล (แผนที่ 1-9)
1. อธิบายโครงสร้างพื้นฐาน syntax และการทำงานของโปรแกรมภาษา C ได้อย่างถูกต้อง
2. เขียนโปรแกรมรับข้อมูลจากผู้ใช้และแสดงผลด้วยคำสั่ง printf/scanf ได้
3. ประกาศตัวแปร ชนิดข้อมูล และใช้งานตัวดำเนินการทางคณิตศาสตร์และตรรกะได้
4. วิเคราะห์ปัญหาและออกแบบ algorithm ด้วย flowchart หรือ pseudocode ก่อนเขียนโปรแกรม

### หน่วยที่ 2 โครงสร้างการตัดสินใจ (แผนที่ 10-18)
5. ใช้คำสั่งเงื่อนไข if, if-else, if-else if และ switch ได้อย่างเหมาะสม
6. วิเคราะห์เงื่อนไขและเลือกโครงสร้างการตัดสินใจที่เหมาะสมกับปัญหา

### หน่วยที่ 3 โครงสร้างการวนซ้ำ (แผนที่ 19-28)
7. เขียนโปรแกรมใช้คำสั่งวนซ้ำ for, while, do-while ได้ถูกต้อง
8. ประยุกต์ใช้ nested loop และ break/continue ในการแก้ปัญหาที่ซับซ้อน

### หน่วยที่ 4 Array และฟังก์ชัน (แผนที่ 29-37)
9. เขียนโปรแกรมโดยใช้ user-defined function, parameter และ return value ได้
10. ใช้งาน Array 1 มิติและ 2 มิติในการเก็บและประมวลผลข้อมูลหลายชุดได้
11. ค้นหาและแก้ไขข้อผิดพลาด (debugging) ด้วยตนเองและด้วย AI Code Analyzer อย่างเป็นระบบ

### หน่วยที่ 5 โครงงานขนาดเล็กและการใช้เทคโนโลยี AI
12. สร้างโครงงานขนาดเล็กที่บูรณาการความรู้หลายหน่วยได้อย่างสร้างสรรค์และมีความรับผิดชอบ
13. ใช้เทคโนโลยี AI เป็นเครื่องมือสนับสนุนการเรียนรู้อย่างมีวิจารณญาณและจริยธรรม
14. ทำงานร่วมกับผู้อื่น แบ่งปันความรู้ และให้ข้อมูลป้อนกลับแก่เพื่อนอย่างสร้างสรรค์

**จุดเชื่อมกับนวัตกรรม** ผลการเรียนรู้ข้อ 11 และ 13 อ้างถึงการใช้ AI โดยตรง จึงเป็นจุดที่เชื่อมหลักสูตรกับ APCC ชัดที่สุด

**ข้อควรระวังเรื่องจำนวนแผนและชั่วโมง** เอกสารโครงสร้างรายวิชาระบุ 80 ชั่วโมง แต่เอกสารวิทยฐานะฉบับร่าง
ระบุ 74 ชั่วโมง ต้องเลือกใช้ให้ตรงกัน และช่วงแผน 1-37 ในระบบครอบคลุมเฉพาะหน่วย 1-4 ส่วนหน่วย 5
ยังไม่ได้กำหนดเลขแผน

  ระดับ 3 Scaffold/Pseudocode → ระดับ 4 ชี้รูปแบบข้อผิดพลาด
- ผู้เรียนกดขอเองทีละระดับ ข้ามระดับไม่ได้ ระบบไม่เลื่อนระดับให้อัตโนมัติ
- **เงื่อนไขก่อนขอ** ต้องส่งงานอย่างน้อย 1 ครั้งและผลยังไม่ผ่านทุกเคส ไม่จำกัดเวลาและจำนวนครั้ง
- **คำใบ้อิงข้อผิดพลาดจริง** ระบบวิเคราะห์ในเครื่องก่อนว่าเคสไหนไม่ผ่าน ผลต่างกันบรรทัดใด
  และตรวจจุดผิดที่พบบ่อย เช่น ลืม & ใน scanf, ใช้ = แทน ==, integer division,
  ตัวแปรไม่ได้กำหนดค่าเริ่มต้น แล้วส่งข้อมูลนี้เป็นฐานให้ AI เขียนคำใบ้
- **ทำงานได้แม้ AI ล่ม** ใช้คำใบ้ที่สร้างในเครื่องแทน
- ปิดอัตโนมัติในโหมดสอบ
- หน้าทดลองใช้สำหรับผู้เยี่ยมชมมี 3 ระดับ ไม่ใช่ 4

## 9. ข้อจำกัดของนวัตกรรม (ต้องเขียนในเล่มเพื่อความตรงไปตรงมา)

### 9.1 ระบบตรวจไม่ได้ว่าผู้เรียนใช้ AI ภายนอกหรือไม่
ผู้เรียนนำโจทย์ไปถาม ChatGPT, Gemini หรือ AI อื่นนอกระบบ แล้วนำโค้ดมาวางส่งได้ทันที
โดยไม่ต้องใช้ AI Scaffolding (คำใบ้) ของระบบเลย **ระบบไม่มีกลไกตรวจจับพฤติกรรมนี้**
และไม่ได้เก็บลายนิ้วมือการพิมพ์หรือประวัติการวางข้อความ

สิ่งที่ระบบทำได้มีเพียงโหมดสอบ (จับเวลา ตรวจการสลับหน้าจอ ปิดเครื่องมือ AI ในระบบ)
และบันทึกการขอคำใบ้ของระบบเอง

**ผลต่อการตีความ** คะแนน E1 สะท้อน "ผลงานที่ส่ง" ไม่ใช่ "ความสามารถที่ผู้เรียนทำได้ด้วยตนเอง"
และจำนวนการขอคำใบ้ที่ต่ำ **ไม่ได้แปลว่าผู้เรียนเก่งขึ้นเสมอไป** อาจแปลว่าไปใช้ AI ทางอื่นแทน

#### ข้อมูลประกอบ: การได้คะแนนเต็มเทียบกับการใช้คำใบ้
วิเคราะห์จากฐานข้อมูลจริง (`tools/analyze-hint-usage.js`) ขอบเขต 20 ข้อที่นับคะแนน
ผู้เรียน 35 คน รวม 692 คู่

| ตัวชี้วัด | จำนวน | ร้อยละ |
|---|---|---|
| คู่ที่ได้คะแนนเต็ม 100 | 639 | 92.3% ของคู่ทั้งหมด |
| ในจำนวนนั้น **ไม่เคยขอคำใบ้เลย** | 564 | **88.3% ของคู่ที่ได้เต็ม** |
| ในจำนวนนั้น เคยขอคำใบ้อย่างน้อย 1 ระดับ | 75 | 11.7% |
| คู่ที่ได้เต็ม **ตั้งแต่ส่งครั้งแรก** | 326 | 47.1% ของคู่ทั้งหมด |
| ในจำนวนนั้น ไม่เคยขอคำใบ้เลย | 318 | 97.5% |

| การใช้คำใบ้รายบุคคล | จำนวน |
|---|---|
| ไม่เคยขอคำใบ้เลยทั้งภาคเรียน | 5 คน (14.3%) |
| ขอคำใบ้ 1-5 ครั้ง | 22 คน |
| ขอคำใบ้มากกว่า 5 ครั้ง | 8 คน |

**การตีความที่ปลอดภัย** ตัวเลขเหล่านี้ **ไม่ใช่หลักฐานว่าผู้เรียนใช้ AI ภายนอก**
และ **ไม่ใช่หลักฐานว่าผู้เรียนทำได้ด้วยตนเอง** อธิบายได้ 3 ทาง
1. โจทย์ส่วนใหญ่เป็นระดับพื้นฐานที่ผู้เรียนทำได้เองอยู่แล้ว (สอดคล้องกับข้อ 9.2)
2. ผู้เรียนใช้ปุ่ม "ทดสอบตัวอย่าง" และ "รัน" แก้ปัญหาเองจนผ่านโดยไม่ต้องขอคำใบ้
3. ผู้เรียนบางส่วนอาจใช้ AI ภายนอกระบบ ซึ่งระบบตรวจไม่ได้

### 9.2 การตรวจเป็นผ่าน/ไม่ผ่านต่อกรณีทดสอบ ไม่ได้วัดคุณภาพโค้ด
ระบบเทียบผลลัพธ์แบบตรงตัวอักษรกับกรณีทดสอบเท่านั้น จึง**ไม่ได้ประเมิน**
- ประสิทธิภาพของอัลกอริทึม เช่น ลูปซ้อนที่ไม่จำเป็น
- การตั้งชื่อตัวแปร การจัดรูปแบบ การเขียนคอมเมนต์
- การใช้ฟังก์ชันหรือโครงสร้างตามที่โจทย์กำหนด

โจทย์ส่วนใหญ่เป็นระดับพื้นฐาน **ถ้าทำได้ก็ได้เต็มทันที ถ้าทำไม่ได้ก็ได้ 0**
คะแนนจึงกระจุกตัวที่ปลายทั้งสองข้าง ไม่กระจายเป็นระฆังคว่ำ

**ผลที่เห็นจริง** ค่า E1 = 89.19 สูงกว่าเกณฑ์ 80 อยู่มาก ควรอธิบายในเล่มว่า
**สูงเพราะธรรมชาติของการตรวจแบบกรณีทดสอบและระดับความยากของโจทย์ ไม่ใช่เพราะผู้เรียนเก่งเกินจริง**
และไม่ควรนำไปเทียบกับคะแนนแบบทดสอบเขียนตอบโดยตรง

**ข้อเสนอพัฒนาต่อ** นำคะแนนคุณภาพโค้ดจาก AI Code Analyzer ที่เก็บไว้แล้วใน `submissions.aiScore`
และ `aiMetrics` มาถ่วงน้ำหนักร่วมกับคะแนนกรณีทดสอบ

### 9.3 เกณฑ์คิดคะแนน: ยึดการส่งครั้งล่าสุด

**เกณฑ์ที่ใช้กับคะแนนในเล่มรายงาน คือคะแนนจากการส่งครั้งล่าสุดของแต่ละกิจกรรม**
ค่า E1 = 89.19 ในหัวข้อ 4 คำนวณด้วยเกณฑ์นี้ทั้งหมด

**ข้อตกลงกับผู้เรียน** ผู้สอนแจ้งผู้เรียนว่าคะแนนยึดการส่งครั้งล่าสุด ผู้เรียนจึงต้องรับผิดชอบ
โค้ดที่ส่งทุกครั้ง และหากต้องการคะแนนที่สูงขึ้นสามารถย้อนกลับไปส่งโค้ดที่เคยทำได้ใหม่
แนวปฏิบัตินี้มุ่งให้การกดส่งเป็นการตัดสินใจที่ผ่านการคิด ไม่ใช่การลองส่งไปเรื่อย ๆ
โดยระบบยังเปิดให้ทดลองรันและทดสอบกับกรณีทดสอบตัวอย่างได้ไม่จำกัดครั้งโดยไม่กระทบคะแนน

**การตั้งค่าในระบบ** ระบบมีตัวเลือกเกณฑ์คิดคะแนนระดับรายวิชา ผู้สอนตั้งค่ารายวิชานี้เป็น
"คะแนนครั้งล่าสุด" ในหน้าจัดการราย และปิดรับคะแนนเพื่อตรึงตัวเลขเมื่อ 27 ก.ย. 2569

### 9.4 ข้อมูลเชิงกระบวนการไม่ได้ถูกบันทึกตลอดภาคเรียน
`runCount` (จำนวนครั้งที่กดรันก่อนส่ง), `timeSpentSeconds` (เวลาที่ใช้ทำโจทย์) และ `hintLevelUsed`
**ไม่เคยถูกบันทึกลงฐานข้อมูลเลย** เพราะกฎความปลอดภัยไม่อนุญาตให้ผู้เรียนแก้ไขเอกสารการส่งงานของตนเอง
และโค้ดกลืน error ไว้เงียบ ๆ แก้แล้วเมื่อ 2026-09-26 แต่**ข้อมูลเก่ากู้ไม่ได้**

**ห้ามอ้างตัวเลขเวลาที่ใช้ทำโจทย์หรือจำนวนครั้งที่ลองรันก่อนส่งในเล่ม**
ถ้าต้องการข้อมูลใกล้เคียงให้ใช้ `usageEvents` (`code_run`, `sample_test`, `ai_hint`)
และ `coachInteractions` ซึ่งบันทึกครบ

2. Achievement นิยาม 13 รายการ ปลดล็อกได้จริง 10 รายการ
3. การตรวจกิจกรรม Loop Autopsy ให้คะแนนเมื่อคำตอบยาวเกิน 20 ตัวอักษร ไม่ได้ตรวจความถูกต้อง
   ควรเรียกว่าคะแนนการมีส่วนร่วม
4. การตั้งค่า "อนุญาต AI Scaffolding (คำใบ้)" และจำนวนคำใบ้สูงสุดในหน้าสร้างกิจกรรม บันทึกได้แต่ระบบไม่บังคับใช้
5. ไม่มีหน้าจอดูประวัติการขอคำใบ้รายบุคคล ต้องส่งออกข้อมูลไปวิเคราะห์เอง
6. เครื่องมือแก้ไขข้อมูลที่ผู้พัฒนาสร้างเองเคยมีข้อผิดพลาดทำให้ค่าเหรียญของผู้เรียน 1 คนเสียหาย
   ตรวจพบและซ่อมได้ภายในวันเดียวกันเพราะมีการสำรองข้อมูลก่อนแก้ทุกครั้ง

### 9.7 ข้อจำกัดด้านขนาดและบริบทของการทดลอง
- ใช้กับผู้เรียน **35-36 คน ห้องเดียว ภาคเรียนเดียว ไม่มีกลุ่มควบคุม**
- ผู้พัฒนาระบบกับผู้สอนเป็นคนเดียวกัน จึงมีโอกาสเกิดอคติในการตีความผล
- เป็นการศึกษาเชิงปฏิบัติการในชั้นเรียนของตนเอง ไม่ใช่การทดลองแบบสุ่มที่สรุปผลทั่วไปได้

## 10. การปรับปรุงระบบรอบล่าสุด (ใช้เขียนหัวข้อการพัฒนานวัตกรรม)

### 10.1 ข้อบกพร่องที่ตรวจพบและแก้ไข
| ปัญหา | ผลกระทบที่พบจริง |
|---|---|
| ช่องโหว่สะสม XP 4 จุด รวมบั๊กที่นับว่า "ผ่านครั้งแรก" ทุกครั้ง | ผู้เรียน 1 คนมี XP 108,765 จากการเล่นมินิเกมรัว 2,615 ครั้ง |
| ยอด XP ถูกเขียนทับด้วยค่าศูนย์ (ผลจาก offline cache) | ผู้เรียน 33 คนจาก 120 คนมียอดต่ำกว่าบันทึกต้นทาง |
| หน้าฝึกเองไม่เคยให้ XP เลยตั้งแต่แรก | ผู้เรียนที่ฝึก 44 ข้อ ได้คะแนนฝึกเอง 2,358 แต่มี XP 10 |
| โค้ดที่เคยส่งไม่ถูกดึงกลับ และโค้ดค้างไม่ผูกกับรหัสผู้เรียน | เปลี่ยนเครื่องแล้วโค้ดหาย เครื่องที่ใช้ร่วมกันเห็นโค้ดของคนก่อน |
| ปุ่มเรียงคะแนนในตาราง E1 ใช้สูตรคนละชุดกับตาราง | ลำดับไม่ตรงกับคะแนนรวมที่แสดง |
| สิทธิ์เขียนไม่พอ ทำให้ AI วิเคราะห์แจ้ง error และข้อมูลเชิงกระบวนการไม่เคยบันทึก | ดูข้อ 9.4 |

### 10.2 การแก้ไขข้อมูลที่ดำเนินการแล้ว (2026-09-26 ถึง 27)
1. ตัด XP ส่วนเกินของผู้เรียนที่กดรัว 108,765 → **4,690** ตามเพดาน 150 XP ต่อวันที่ระบบกำหนดไว้เดิม
   ทำเครื่องหมายยกเลิก 2,606 รายการ **ไม่ลบประวัติ**
2. เติม XP ย้อนหลังให้การฝึกเอง **48 คน 346 รายการ รวม 4,346 XP**
3. คำนวณยอด XP ใหม่จากบันทึกต้นทางให้ **34 คน** ตรวจซ้ำแล้วยอดไม่ตรง 0 คนจาก 120 คน
4. ซ่อมค่าเหรียญที่เสียหาย 1 คน
5. ปิดรับคะแนนรายวิชา 1/69 และ 1/68 เพื่อตรึงตัวเลข

ทุกการแก้ไขสำรองข้อมูลเดิมเป็นไฟล์ JSON และบันทึกเหตุผลไว้ใน `xpCorrections`

## 11. วงรอบการพัฒนาที่เขียนเป็นเนื้อหาในเล่มได้

1. **พบปัญหาจากการใช้จริง** โควตา AI ฟรีหมดระหว่างคาบ ผู้เรียนฝึกเองไม่ได้
   → **พัฒนา** คลังโจทย์ 34 ข้อพร้อมกรณีทดสอบที่ตรวจสอบด้วยคอมไพเลอร์จริง ใช้งานได้โดยไม่ต้องพึ่ง AI
2. **พบจากการวิเคราะห์ข้อมูล** การส่งซ้ำไม่มีต้นทุน ทำให้เกิดการลองส่งโดยไม่ไตร่ตรอง 77 กรณี
   → **พัฒนา** คำเตือนก่อนกดส่งและป้ายบอกเกณฑ์คิดคะแนนในหน้าจอผู้เรียน เพื่อให้ผู้เรียนรู้กติกาก่อนตัดสินใจ
   พร้อมทำให้หน้าคะแนนของผู้เรียนและตารางสรุปของผู้สอนคิดคะแนนด้วยเกณฑ์และคะแนนดิบชุดเดียวกัน
3. **พบจากการตรวจสอบระบบ** ช่องโหว่การสะสม XP และบั๊กที่ทำให้ยอดคะแนนเพี้ยน
   → **พัฒนา** เพดาน XP รายวันแยกตามแหล่งที่มา และเครื่องมือตรวจสอบข้อมูล 6 ตัวที่สำรองและตรวจย้อนหลังได้
4. **พบความต้องการด้านความน่าเชื่อถือของข้อมูล** ตัวเลขขยับหลังส่งออกรายงาน
   → **พัฒนา** ระบบล็อกคะแนนรายวิชาที่ยังให้ผู้เรียนใช้ระบบต่อได้
