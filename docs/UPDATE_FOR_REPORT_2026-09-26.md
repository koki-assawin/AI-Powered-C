## 1. สิ่งที่เปลี่ยนไปจากเอกสารชุดก่อน (ต้องแก้ในเล่ม)

### 1.1 ชื่อกลไกคำใบ้ — ใช้ชื่อเดียวกันทั้งระบบแล้ว (commit `46cb4b2`)
- ชื่อที่ผู้ใช้เห็นทุกหน้าจอคือ **"AI Scaffolding (คำใบ้)"**
- คำอธิบายมาตรฐานคือ **"คำใบ้ไล่ระดับแบบโสเครติส 4 ระดับ"**
- แก้ครบทุกหน้า: หน้าเขียนโค้ดของนักเรียน, แดชบอร์ดนักเรียน, เกม AI Ethics Quiz, หน้าทดลองใช้,
  แดชบอร์ดครู (KPI "ขอ AI Scaffolding (คำใบ้) ระดับ 3"), หน้าวิเคราะห์นักเรียน, หน้าสร้างกิจกรรม,
  หน้าจัดการโจทย์, Usage Analytics ของผู้ดูแลระบบ และนโยบายความเป็นส่วนตัว
- คำว่า "Socratic" ไม่ปรากฏบนหน้าจอผู้ใช้แล้ว และ prompt ที่ส่งให้ AI ก็สั่งห้ามเรียกตัวเองว่า Socratic Coach
- **สิ่งที่รายงานควรใช้:** เรียกกลไกนี้ว่า "AI Scaffolding (คำใบ้)" ให้ตรงกับหน้าจอ ส่วนคำว่า "โสเครติส"
  ใช้ได้ในคำอธิบายเชิงทฤษฎี
- **หมายเหตุ:** คู่มือ `STUDENT_GUIDE.md` และ `TEACHER_GUIDE.md` ยังใช้คำเก่าว่า "ขอ Hint" อยู่ ยังไม่ได้แก้

### 1.2 คลังโจทย์ฝึกเองแบบไม่ใช้ AI (commit `c2fc8e9`) — ของใหม่ที่ควรเขียนถึง
- เพิ่ม `js/practiceBank.js` บรรจุ **โจทย์ 34 ข้อ กรณีทดสอบรวม 121 เคส** ครอบคลุมครบทั้ง 5 หน่วย
  และครบทุกหัวข้อในเมนูเลือกหัวข้อของภาษา C
- แบ่งตามระดับ: ง่าย 11 ข้อ ปานกลาง 16 ข้อ ยาก 7 ข้อ
- **เฉลยอ้างอิงทุกข้อถูกคอมไพล์และรันด้วย gcc จริง** เพื่อสร้างผลลัพธ์ที่ถูกต้องของทุกกรณีทดสอบ
  จึงไม่มีเคสที่เฉลยผิด
- หน้าฝึกเองมีปุ่ม "🎯 สุ่มโจทย์จากคลัง" ได้โจทย์ทันทีโดยไม่เรียก AI และเมื่อ AI ใช้ไม่ได้
  (โควตาหมด/เครือข่ายล่ม) ระบบจะหยิบโจทย์จากคลังมาให้อัตโนมัติพร้อมแจ้งผู้เรียน
- ตอนส่งคำตอบ โจทย์จากคลังใช้กรณีทดสอบที่มากับโจทย์ ไม่เรียก AI ซ้ำ
- บันทึกการฝึกเก็บ `problemSource` เป็น `bank` หรือ `ai` แยกได้ว่าข้อไหนมาจากไหน

**ที่มาของการพัฒนา (ใช้เขียนเป็นวงรอบ PDCA ได้):** เดิมหน้าฝึกเองเรียก AI สองครั้งต่อการฝึกหนึ่งข้อ
(สร้างโจทย์ + สร้างกรณีทดสอบ) เมื่อโควตา Gemini แบบฟรีหมด นักเรียนจึงฝึกไม่ได้เลย
จึงพัฒนาคลังโจทย์สำเร็จรูปขึ้นมาแก้ข้อจำกัดนี้

## 2. ข้อบกพร่องที่ตรวจพบและแก้ไขแล้ว (เนื้อหาสำหรับหัวข้อ "การปรับปรุงพัฒนานวัตกรรม")

### 2.1 ช่องโหว่การสะสมคะแนน XP (commit `8c9ebfd`)
ตรวจพบจากข้อมูลจริง นักเรียน 1 คนมี XP 108,765 ขณะที่อันดับสองมี 23,858

**สาเหตุที่พบ 4 ข้อ**
1. ฟังก์ชันตรวจ "ผ่านครั้งแรก" ค้นหาด้วย field `passed` ที่ระบบไม่เคยบันทึก ทำให้นับว่าเป็นครั้งแรกทุกครั้ง
   และจ่ายโบนัสซ้ำได้ไม่จำกัด
2. ส่งซ้ำข้อที่เคยผ่านแล้วได้ XP เต็มทุกครั้ง
3. งานในทีม (TeamSync) สลับสถานะไปมาได้ XP ทุกครั้ง
4. กิจกรรมรูปแบบใหม่ส่ง argument ผิดตำแหน่ง ทำให้ไม่เคยจ่าย XP เลย

**การแก้ไข** ตรวจผ่านครั้งแรกจากคะแนนจริง, ส่งซ้ำได้สูงสุด 5 XP, เพดาน XP รายวันแยกตามแหล่งที่มา
(ส่งงาน 300, Ethics Quiz 160, งานในทีม 60, peer feedback 60), งานในทีมให้ XP ครั้งเดียวต่องาน
ทดสอบตรรกะด้วยฐานข้อมูลจำลอง 8 กรณี ผ่านทั้งหมด

### 2.2 ยอด XP สะสมถูกเขียนทับด้วยค่าศูนย์ (commit `d23ce9f`)
- ตรวจพบนักเรียน **33 คนจาก 120 คน** ที่ยอด XP ในโปรไฟล์ต่ำกว่าบันทึกต้นทาง (`xpLedger`) เช่น
  นักเรียนคนหนึ่งมีบันทึก 3,825 XP จาก 152 รายการ แต่โปรไฟล์แสดง 10 XP
- สาเหตุ: ฟังก์ชันสร้างยอดสะสมเขียนค่าเริ่มต้นทับเมื่ออ่านเอกสารไม่พบ ประกอบกับระบบเปิด offline
  persistence ทำให้การอ่านอาจได้คำตอบจากแคชที่ว่างเปล่าเมื่อเครือข่ายสะดุด
- แก้โดยเปลี่ยนไปใช้ increment(0) คู่กับ merge ซึ่งไม่แตะค่าเดิมที่มีอยู่
- เพิ่มการป้องกันในตัวสร้างข้อมูลวิจัย ไม่ให้เขียนทับบัญชีที่มี XP จากการใช้งานจริง

### 2.3 หน้าฝึกเองไม่เคยให้ XP (commit `f1737da`)
- ตรวจพบว่าหน้าฝึกเองไม่เคยเรียกฟังก์ชันให้ XP เลยตั้งแต่แรก คะแนนฝึกเองจึงแยกจากระบบ XP โดยสิ้นเชิง
- ตัวอย่างผลกระทบ: นักเรียนที่ฝึกไป 44 ข้อ ได้คะแนนฝึกเอง 2,358 คะแนน แต่มี XP เพียง 10
- แก้แล้ว ส่งคำตอบฝึกเองได้ XP ตามสัดส่วนกรณีทดสอบที่ผ่าน (ง่าย 10 / ปานกลาง 15 / ยาก 25 XP)
  เพดาน 200 XP ต่อวัน

### 2.4 โค้ดที่เคยส่งไม่ถูกดึงกลับมาให้ผู้เรียน (commit `634543c`)
- เดิมโค้ดที่พิมพ์ค้างเก็บใน localStorage ของเบราว์เซอร์เท่านั้น เปลี่ยนเครื่องหรือเปลี่ยนโปรไฟล์
  Chrome แล้วช่องแก้โค้ดจะว่าง ทั้งที่โค้ดที่กดส่งถูกเก็บบน Firestore ครบ
- แก้ให้ดึงโค้ดจากการส่งครั้งล่าสุดกลับมาอัตโนมัติ พร้อมแจ้งผู้เรียนว่ากู้มาจากไหน
- พบปัญหาความเป็นส่วนตัวร่วมด้วย: คีย์เก็บโค้ดค้างไม่มีรหัสนักเรียนกำกับ ทำให้ในห้องคอมที่ใช้เครื่อง
  ร่วมกัน นักเรียนคนถัดไปเห็นโค้ดของคนก่อนหน้า แก้โดยผูกคีย์กับรหัสนักเรียนแล้ว

## 3. เครื่องมือตรวจสอบความถูกต้องของข้อมูล (สร้างใหม่ ใช้เป็นหลักฐานความโปร่งใสได้)

อยู่ในโฟลเดอร์ `tools/` ทุกตัวเป็นโหมดทดลองโดยค่าเริ่มต้น ต้องใส่ `--apply` เองจึงจะเขียนข้อมูล
และสำรองข้อมูลเดิมเป็นไฟล์ JSON ก่อนเสมอ

| เครื่องมือ | หน้าที่ |
|---|---|
| `tools/xp-audit.js` | รายงาน XP ของนักเรียนรายคน แยกตามแหล่งที่มาและตามนาที (อ่านอย่างเดียว) |
| `tools/xp-fix-farmed.js` | ตัด XP ส่วนเกินจากการกดรัว โดย**ทำเครื่องหมายยกเลิก ไม่ลบประวัติ** แล้วคำนวณยอดใหม่ |
| `tools/xp-rebuild-stats.js` | คำนวณยอด XP ใหม่จากบันทึกต้นทาง `xpLedger` |
| `tools/xp-backfill-selfpractice.js` | เติม XP ย้อนหลังให้การฝึกเองที่ทำไปแล้วแต่ไม่เคยได้ XP |

ทุกการแก้ไขบันทึกเหตุผล เวลา และค่าก่อน-หลัง ไว้ใน collection `xpCorrections`

**สถานะปัจจุบัน:** ยังไม่ได้แก้ข้อมูลจริงแม้แต่รายการเดียว รันได้เฉพาะโหมดทดลอง เพราะติดโควตาการอ่าน
ข้อมูลของ Firebase แผนฟรี (50,000 ครั้งต่อวัน) รอโควตารีเซ็ต

## 4. ข้อมูลเชิงประจักษ์ที่ได้จากการตรวจสอบ (ใช้อ้างในเล่มได้)

ตัวเลขจากฐานข้อมูลจริงของรายวิชา ว31281 ภาคเรียน 1/69 ณ 2026-09-25

| รายการ | จำนวน |
|---|---|
| นักเรียนลงทะเบียน | 36 คน |
| โจทย์ทั้งหมดในรายวิชา | 29 ข้อ |
| การส่งงานทั้งหมด | 3,548 ครั้ง (เฉลี่ยประมาณ 3-4 ครั้งต่อคนต่อข้อ) |
| อัตราผ่านทุกกรณีทดสอบ | 32% |
| นักเรียนที่ใช้การฝึกเอง | 17 คน |

| คะแนนฝึกเองรวม | 12,175 คะแนน |

## 5. ประเด็นเกณฑ์การคิดคะแนน (อยู่ระหว่างตัดสินใจ — ต้องระบุให้ตรงในเล่ม)

**กติกาที่ใช้อยู่จริงตลอดภาคเรียน 1/69 คือ "คะแนนดีที่สุด"**
ระบบบันทึกคะแนนใหม่เฉพาะเมื่อสูงกว่าเดิม (`js/grader.js:344`) ทั้งสมุดเกรดของนักเรียนและตาราง E1
ของครูใช้คะแนนดีที่สุดเหมือนกัน

**ครูกำลังพิจารณาเปลี่ยนเป็น "คะแนนครั้งล่าสุด"** ด้วยเหตุผลว่าจะทำให้ผู้เรียนคิดวิเคราะห์ก่อนกดส่ง
แทนการลองส่งซ้ำโดยไม่ไตร่ตรอง โดยระบบมีปุ่ม "ทดสอบตัวอย่าง" และ "รัน" ให้ทดลองได้ไม่จำกัด
โดยไม่กระทบคะแนนอยู่แล้ว

**ยังไม่ได้ข้อสรุปว่าจะใช้ย้อนหลังกับ 1/69 หรือเริ่มที่ 2/69** เมื่อได้ข้อสรุปจะปรับปรุงไฟล์นี้
ผู้เขียนเล่มควรรอยืนยันก่อนเขียนหัวข้อนี้

## 7. สิ่งที่ยังไม่ได้ทำ (อย่าเขียนในเล่มว่าเสร็จแล้ว)

1. ยังไม่ได้แก้ข้อมูล XP ของนักเรียนจริง (รอโควตา Firebase)
2. คู่มือครูและคู่มือนักเรียนยังใช้ชื่อฟีเจอร์เก่าในบางจุด
3. ยังไม่ได้ตัดสินใจเรื่องเกณฑ์คิดคะแนน (ข้อ 5)
4. การตั้งค่า "อนุญาต AI Scaffolding (คำใบ้)" และ "จำนวนคำใบ้สูงสุด" ในหน้าสร้างกิจกรรม
   ยังบันทึกค่าได้แต่ระบบไม่ได้นำไปบังคับใช้
5. Achievement นิยามไว้ 13 รายการ แต่ปลดล็อกได้จริง 10 รายการ
6. การแจ้งเตือนความเสี่ยงเป็นการวิเคราะห์ด้วยกฎเกณฑ์จากคะแนนย้อนหลัง **ไม่ใช่โมเดล Machine Learning**
