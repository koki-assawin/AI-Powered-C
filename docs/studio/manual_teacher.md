## 2. เปิดใช้ Studio ในรายวิชา

1. เมนู **จัดการ → จัดการรายวิชา** → กด ✏️ แก้ไขรายวิชา
2. เลื่อนลงไปที่กล่องสีม่วง **🎨 เปิดใช้ APCC Studio** → ติ๊กเปิด → เลือก template
   - **ว23207**: เปิดครบทุกฟีเจอร์ มี 4 ด่านทักษะ
   - **ว23103 บทที่ 2**: เปิด Parsons, Learning Hub, ด่านทักษะ 2 ด่าน และ Explain-Back แต่ไม่เปิด Project Studio
3. ปรับเปิด/ปิดได้ทีละฟีเจอร์ → กด **💾 บันทึกการตั้งค่า Studio** (แยกจากปุ่มบันทึกรายวิชาเดิม)

> รายวิชา ว31281 ทุกรุ่น และรายวิชาทดลองใช้ (Sandbox1–3) เป็นข้อมูลวิจัยของรายงาน ระบบจะขึ้น 🔒 และไม่ให้เปิด Studio

## 3. ชุดโจทย์ (Course Template Pack)

เมนู **จัดการ → APCC Studio ชุดโจทย์** (ภาพ `04`–`08`)

1. เลือกรายวิชาที่เปิด Studio แล้ว
2. เลือกชุดโจทย์: ไฟล์ตัวอย่างในระบบ (ว23207 57 ข้อ, ว23103 10 ข้อ) หรือ **📂 อัปโหลดไฟล์ JSON**
3. ดู **ตัวอย่างก่อนบันทึก (dry-run)**: ข้อไหน "ใหม่", "มีแล้ว" หรือ "ข้อมูลผิด" ระบบตรวจซ้ำจากรหัสหน้าชื่อโจทย์ เช่น `W207-04-2` จึงไม่สร้างซ้ำ
4. **🧪 ตรวจเฉลยก่อนนำเข้า**: ระบบรันเฉลยกับทุก test case ผ่าน runner เดิม ใช้เวลาประมาณ 1–2 นาทีต่อ 50 กรณี ควรกดนอกเวลาเรียน
5. เลือกปุ่มตามกรณี
   - **➕ นำเข้าโจทย์ใหม่**: โจทย์ที่นำเข้าจะยัง "ไม่เผยแพร่" ครูตรวจแล้วกดเผยแพร่ในหน้าจัดการโจทย์เดิม
   - **✨ เติมข้อมูล Studio ให้โจทย์เดิม**: ใช้กับรายวิชาที่มีโจทย์อยู่แล้ว เช่น ว23207 ที่นำเข้าไว้ก่อนมี Studio
     - เพิ่มเฉพาะฟิลด์ใหม่ (ประเภท Parsons, คำใบ้ 4 ระดับ, skillTag, โค้ดตั้งต้น)
     - ไม่แก้ชื่อ คำอธิบาย test case หรือคะแนน
     - ทุกข้อบันทึกค่าก่อนแก้ไว้ เพื่อตรวจย้อนหลังได้
   - **💾 บันทึกชุดนี้ลงคลัง template**: เก็บชุดโจทย์รวมเฉลยไว้ นักเรียนมองไม่เห็นคลังนี้
   - **⬇️ ส่งออกรายวิชาเป็น template**: ได้ไฟล์ JSON ไม่มีข้อมูลนักเรียน ส่งต่อให้ครูโรงเรียนอื่นได้

**รูปแบบไฟล์ JSON** (1 โจทย์):
```json
{ "id": "W207-04-2", "course": "ว23207", "language": "python", "plan": 4,
  "title": "เลขคู่หรือเลขคี่", "level": "ง่าย | ปานกลาง | ท้าทาย | สอบ", "type": "code | parsons",
  "description": "...", "input_format": "...", "output_format": "...",
  "starter_code": "", "solution": "...", "hints": ["ระดับ 1", "2", "3", "4"], "hints_enabled": true,
  "test_cases": [ { "input": "4\n", "expected_output": "คู่\n", "visible": true } ] }
```
- `level: "สอบ"` = ข้อสอบ (ปิดคำใบ้และ AI)
- โจทย์ Parsons ใส่บรรทัดใน `parsons.lines` และบรรทัดหลอกใน `parsons.distractors` หรือใส่เป็นบรรทัดคอมเมนต์ `# ...` ใน `starter_code` ก็ได้ โดยใช้การย่อหน้าจาก `solution` เป็นเฉลย

## 4. Parsons, คำใบ้จากครู และ Learning Hub ภาษาไพทอน

- **Parsons** (ภาพ `10`–`13`): โจทย์ `type: parsons` จะแสดงเป็นบล็อกให้ลากหรือคลิกเรียง และปรับการย่อหน้าได้
  - ปุ่ม "ตรวจลำดับ" บอกบรรทัดแรกที่ยังผิด ไม่นับคะแนน
  - คะแนนจริงมาจากปุ่ม **Submit** เดิม ซึ่งตรวจด้วย test case ตามปกติ
- **คำใบ้จากครู** (ภาพ `14`): ปุ่มคำใบ้เดิม ระดับ 1→4 จะแสดงคำใบ้ที่ครูเขียนไว้ใน `hints` ก่อน
  - **ไม่เรียก AI** จึงใช้ได้แม้โควตา Gemini หมด
  - ใช้ครบ 4 ระดับแล้ว นักเรียนกด 🔄 วิเคราะห์โค้ดที่ส่งล่าสุด เพื่อให้ AI ช่วยต่อได้
- **Learning Hub** (ภาพ `15`): รายวิชาไพทอนที่เปิด Studio จะมีหัวข้อ built-in 12 หัวข้อ ครูยังเพิ่มหัวข้อเองได้ที่ **จัดการเนื้อหา** เหมือนเดิม
  นักเรียนเข้าได้จากลิงก์ 📚 Learning Hub ในกล่อง APCC Studio บนแดชบอร์ด หรือปุ่ม 🧪 Learning Tools ในหน้ารายวิชา
  เมนู "เรียน → Learning Tools" ไม่มีรายวิชาติดไปด้วย จึงไม่แสดงหัวข้อไพทอน

## 5. ด่านทักษะและ Explain-Back

เมนู **จัดการ → APCC Studio ด่านทักษะ** (ภาพ `21`–`23`)
- **ตั้งด่าน**: ด่านละกลุ่ม skillTag
  - ค่าเริ่มต้นของ ว23207: ด่าน 1 ลำดับ/I-O, ด่าน 2 การตัดสินใจ, ด่าน 3 การทำซ้ำ, ด่าน 4 ลิสต์และฟังก์ชัน
  - ผ่านด่าน = ผ่านโจทย์ฝึกที่เผยแพร่แล้วครบทุก test case อย่างน้อย 60% ของจำนวนข้อ (ปรับได้) ไม่นับข้อสอบ
  - ผ่านด่านบังคับครบ ⇒ นักเรียนปลดล็อกขั้น **สร้าง** และเข้า Project Studio ได้
- **ความก้าวหน้า**: ตารางนักเรียน × ด่าน คำนวณสดจากการส่งงานจริง
- **Explain-Back** ไม่มีผลกับคะแนน ใช้ประกอบการสังเกตความเข้าใจ
  - ถามหลังนักเรียนผ่านโจทย์ระดับปานกลางหรือยาก
  - นักเรียนเลือก "อธิบายโค้ด" (AI ให้ระดับ 0–3) หรือ "ทำนายผล" กับข้อมูลที่ยังไม่เคยเห็น (ระบบตรวจเอง)
  - ระดับที่มีเครื่องหมาย `*` คือประเมินด้วยเกณฑ์สำรองตอน AI ใช้ไม่ได้ ระดับสูงสุด 2 ควรตรวจซ้ำ

## 6. Project Studio (ขั้นสร้าง)

นักเรียนเข้าจากปุ่ม **🛠️ เปิด Project Studio** บนแดชบอร์ด ซึ่งปรากฏหลังปลดล็อก (ภาพ `24`–`27`)
1. **ทีม**: นักเรียนสร้างหรือเข้าร่วมทีมที่ **TeamSync** (เมนูนักเรียน) ด้วยรหัสทีม 6 ตัว
2. **บอร์ด 5 ขั้น**: เข้าใจผู้ใช้ (สัมภาษณ์ ≥ 2 คน) → นิยามปัญหา → ออกแบบ (≥ 3 ไอเดีย) → สร้างต้นแบบ → ทดสอบกับผู้ใช้ 2 รอบ
3. **Kit A — เว็บแอป Streamlit**: เขียนและรันในเบราว์เซอร์ได้เลย ไม่ต้องติดตั้ง Python ทุกครั้งที่บันทึกจะได้ "รุ่น" ไว้เป็นหลักฐาน
   **Kit B — Colab**: วิเคราะห์ข้อมูลจาก Google Forms แล้ววางลิงก์ Colab
4. **Design Coach**: ปุ่มขอคำถามชวนคิด AI จะถามนำ ไม่ทำงานแทน ถ้า AI ใช้ไม่ได้ จะใช้คลังคำถามแทน

> ครั้งแรกที่รันเว็บแอป แต่ละเครื่องต้องดาวน์โหลดประมาณ 30 MB ห้องคอมที่เน็ตช้าควรเปิดค้างไว้ก่อนเริ่มคาบ หรือให้รันทีละกลุ่ม
> บอกนักเรียนว่าบันทึกสัมภาษณ์ห้ามใส่ข้อมูลส่วนตัวของผู้ถูกสัมภาษณ์ เพราะเพื่อนในรายวิชาอ่านได้

## 7. ประเมินตามรูบริก และส่งคะแนนเข้า SGS

เมนู **จัดการ → APCC Studio ประเมินโปรเจกต์** (ภาพ `29`–`30`)
- รูบริก ว23207: 5 เกณฑ์ × 4 ระดับ = 20 คะแนน
  - เกณฑ์ 1–4 ให้คะแนนรายทีม: เข้าใจปัญหาและผู้ใช้, แนวทางแก้ปัญหา, การทำงานของโปรแกรม, การทดสอบและปรับปรุง
  - เกณฑ์ 5 "ความเข้าใจโค้ด" ให้คะแนน **รายบุคคล**
- กด **ประเมิน** ที่โปรเจกต์ → ดูหลักฐานครบ (บอร์ด 5 ขั้น, เว็บแอปทุกรุ่น, Explain-Back รายคน, คำแนะนำจากเพื่อน)
- **🤖 ให้ AI ร่างความเห็น**: AI ร่างระดับและความเห็นจากหลักฐาน ถ้า AI ใช้ไม่ได้ จะร่างจากข้อมูลในระบบแทน
  - ร่างจากข้อมูลในระบบให้ระดับทีมสูงสุด 3 ส่วนระดับ 4 ครูเป็นคนตัดสิน
  - เกณฑ์ 5 ถ้าไม่มีข้อมูล Explain-Back ระบบจะไม่เดา
- ครูแก้ระดับและความเห็น → **💾 บันทึกร่าง** (ทีมยังไม่เห็น) หรือ **📢 ยืนยันและเผยแพร่ให้ทีม**
- **⬇️ ส่งออกคะแนน CSV (SGS)**: 1 แถวต่อนักเรียน (ห้อง เลขที่ รหัส ชื่อ คะแนนแต่ละเกณฑ์ รวม) เปิดใน Excel ได้ แล้วนำไปกรอก SGS
  คะแนนนี้ **ไม่เข้าสมุดคะแนนเดิมของ APCC**

## 8. แกลเลอรี และพอร์ตโฟลิโอ (ขั้นแบ่งปัน)

- ในหน้าประเมินโปรเจกต์ กล่อง **🌏 แกลเลอรีผลงาน** → ใส่คำแนะนำผลงานสั้นๆ → **อนุมัติขึ้นแกลเลอรี** (ภาพ `32`)
  - ระบบเก็บสำเนาผลงาน ณ วันนั้น และเลื่อนสมาชิกทีมไปขั้น **แบ่งปัน**
  - ถ้าต้องการนำออก กด "🙈 ซ่อน"
- **แกลเลอรี** `#/studio/showcase?course=…`: ทุกคนในรายวิชาเปิดดูและลองใช้เว็บแอปของเพื่อนได้ (ภาพ `35`)
- **พอร์ตโฟลิโอ**: รวมด่านที่ผ่าน, โจทย์ที่ผ่าน, Explain-Back, โปรเจกต์ และผลประเมินที่เผยแพร่ กด 🖨️ เพื่อพิมพ์หรือบันทึกเป็น PDF (ภาพ `36`)
  ครูเปิดของนักเรียนรายคนได้จากลิงก์ "พอร์ต" ในหน้า Analytics

## 9. Studio Analytics

เมนู **จัดการ → APCC Studio Analytics** (ภาพ `33`) แยกจากหน้าวิเคราะห์นักเรียนเดิม
- ภาพรวม: จำนวนที่ปลดล็อกขั้นสร้างและขั้นแบ่งปัน, โปรเจกต์, Explain-Back, คำใบ้จากครู, Parsons
- อัตราผ่านแต่ละด่าน, เวลาเฉลี่ยต่อการส่ง และระดับคำใบ้เฉลี่ยรายด่าน
- ตารางรายบุคคลใช้รหัส **S01, S02, …** แทนชื่อ (ติ๊ก "แสดงชื่อ" เพื่อดูบนจอเท่านั้น)
- **⬇️ CSV ปกปิดตัวตน**: ไม่มีชื่อ รหัสนักเรียน หรือ uid ใช้ประกอบรายงานวิจัยได้

## 10. ก่อนใช้กับนักเรียนจริง (ทำครั้งเดียว)

1. Deploy กฎ Firestore ใหม่: `firebase deploy --only firestore:rules`
2. รวม branch `feature/apcc-studio-v6` เข้า `main` แล้ว push ขึ้น GitHub Pages
3. เปิด Studio ที่รายวิชา ว23207 → หน้าชุดโจทย์ → เลือกไฟล์ ว23207 → **✨ เติมข้อมูล Studio** (57 ข้อ)
4. ตรวจหน้าตั้งด่านว่า skillTag ครบ (condition, function, io, list, loop) แล้วกดบันทึกด่าน
5. เปิดเผยโจทย์ตามแผนการสอน (เดิม) — ด่านนับเฉพาะโจทย์ที่เผยแพร่แล้ว

## 11. คำถามที่พบบ่อย

| ปัญหา | วิธีแก้ |
|---|---|
| หน้า Studio ขึ้น "กำลังโหลด APCC Studio..." นาน | ครั้งแรกระบบโหลดไฟล์เพิ่ม รอ 2–5 วินาที ถ้าค้าง กด Ctrl+F5 |
| นักเรียนไม่เห็นปุ่ม Project Studio | ยังผ่านด่านไม่ครบ ตรวจที่แท็บความก้าวหน้า หรือรายวิชายังไม่มีโจทย์ที่เผยแพร่ในด่านนั้น |
| เว็บแอปไม่แสดงผล | ตรวจอินเทอร์เน็ต (ต้องโหลดจาก jsDelivr) แล้วกด ▶ รันเว็บแอป อีกครั้ง ถ้าโค้ดผิด Streamlit จะแสดง error ในกรอบ |
| Explain-Back / Design Coach ได้ผลแบบสำรอง | โควตา Gemini หมดหรือไม่มี key ระบบยังใช้งานต่อได้ ครูตรวจซ้ำรายการที่มี `*` |
| นักเรียนเรียน 2 วิชาที่ใช้ Project Studio | TeamSync ให้ 1 คนอยู่ได้ 1 ทีมทั้งระบบ ควรใช้ทีมเดียวกัน หรือทำโปรเจกต์ทีละวิชา |

## 12. ข้อมูลที่ Studio เก็บ (คอลเลกชันใหม่ทั้งหมด)

`studio_templates` · `studio_events` · `studio_skillGates` · `studio_progress` · `studio_explainBack` · `studio_projects` (+`versions`) · `studio_rubrics` · `studio_reviews` · `studio_showcase`
ส่วน `projectTeams` เป็นของ TeamSync เดิม เพิ่มเฉพาะกฎให้ใช้งานได้

คอลเลกชันเดิม (`submissions`, `grades`, `usageEvents`, `coachInteractions` ฯลฯ) ไม่ถูกเปลี่ยนรูปแบบ
